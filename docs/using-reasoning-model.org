* What can be used today

This document explains *how to run the project*. The companion
[[file:reasoning.org][How it works]] document explains the implementation, with annotated MLPL
blocks that reproduce the library files through tangling.

As of 2026-09-29, a real pretrained Qwen3 8B demo runs through the existing
Rust HTTP dynamic library and local Ollama GPU inference. MLPL owns the
prompts, controls and final-answer verifier. Run the live commands below;
[[file:native-reasoning-demo.md][the demo contract]] records the exact boundary, provenance and measurements.
This is an inference-only workaround authorized by the user, not a
project-trained checkpoint or the pure-MLPL 0.6B forward pass.

Verifier, synthetic-model generation, scoring and scripted
refinement are runnable. The real tokenizer and verified downloads work
with the [[file:extension-integration.md][documented adapters]]. The named-tensor loader passes authored-file
tests and now loads the real checkpoint in 101.45 seconds. Generation still
fails its 32 GiB address-space budget, as documented below. No trained
reasoning checkpoint, real-model accuracy or learning improvement is claimed.

Open this file in Emacs Org mode. Enable shell Babel evaluation in your own
Emacs configuration, inspect each block, then use =C-c C-c= to run it.
Blocks run from the repository root via =:dir ..=. They respect your Babel
confirmation setting and never run merely by opening or exporting this document. MLPL code lives
in the implementation document; this guide uses the same thin shell recipes
that an operator runs from a terminal.

* Real method selection — awaiting responder acceptance

Once the real responder is validated, the guide will show the same prompt
under each supported method, with explicit budgets and provenance:

| Method | What the user controls | Interpretation |
|--------+------------------------+----------------|
| Greedy | Token limit and stop id | Highest-scoring next token |
| Sampling | Seed, temperature, top-p, token limit | A reproducible sampled continuation |
| Self-consistency | Distinct seeds and N | Votes on extracted normalized answers |
| Best-of-N | Candidate seeds and scorer | First maximum score, not proof of correctness |
| Refinement | Initial seed and critique/revision pairs | Retain a revision only if score does not fall |

See [[file:sampling.md][sampling]], [[file:self-consistency.md][voting]], [[file:scoring.md][scoring]] and [[file:self-refinement.md][refinement]] for the implemented
contracts. Their APIs exist today; real-model examples still need validation.

** Does it reason yet, and how good is it?

The pretrained external model now produces verified answers through the
native extension path. On five authored cases, thinking off completed 5/5
correct in 42.17 s; thinking on completed 2/5 correct in 184.47 s and
truncated three responses at 1536 tokens. This is demo readiness, not
held-out accuracy. The follow-up at 3072 tokens completes 5/5 in both modes:
direct 39.16 s, thinking 204.74 s. It fixes truncation without showing a
quality advantage. The runner now defaults to 3072; set =DEMO_MAX_NEW=1536=
to repeat the original cap. See [[file:reasoning-results.org][the reproducible research report]] and its
[[file:reasoning-results.html][standalone HTML]]. No project-trained reasoning improvement is claimed.

For the pure-MLPL reference model, the verifier,
tiny forward pass, sampling, voting, scoring and refinement components are
tested, but the real checkpoint has emitted no answer here. GRPO and
distillation are still queued. A passed software test, completed weight load
or convincing scripted explanation is not a reasoning-quality score. The
current reference-path real-model accuracy is *unknown*, not zero percent.

The frozen six-problem MATH-500 pilot has now run both modes at seeds 42
and 43: zero thinking gains, one truncation regression, and 5.85 times the
request time. Primary scores are 5/6 versus 4/6 at seed 42 and 5/6 versus
5/6 at seed 43. Each mode and seed has one false negative from a choice-format
normalization gap; manual review is separate. The choice-v2 post-hoc replay
now corrects those four grades automatically: 6/6 versus 5/6 at seed 42,
and 6/6 versus 6/6 at seed 43. The original primary scores are preserved.
There are still zero thinking gains and one truncation regression.
See [[file:heldout-pilot-protocol.md][the frozen protocol]]
and the results report. =just reasoning-pilot= runs 24 new calls;
=scripts/replay-heldout-pilot out/native-reasoning/run-s69Yj0sQ= regrades
the retained local evidence without inference.

** Measuring reasoning quality after generation becomes viable

Begin with a fixed, held-out MATH-500 subset for an inexpensive integration
check, then evaluate all 500 only after the measured runtime permits it.
Never train on evaluation questions or select prompts/seeds on the final
test results. Store per-question responses and verifier decisions so the
aggregate can be audited.

| Measure | What to report |
|---------+----------------|
| Task success | Correct verified final answers divided by attempted questions; failures/truncations remain visible |
| Completion reliability | Valid completions, parse failures, timeouts, memory failures and exhausted token budgets |
| Method improvement | Direct-answer versus chain-of-thought versus repeated sampling/voting, on the same questions and comparable total token/time budgets |
| Variability | Fixed published seeds, repeated sampled runs and uncertainty for accuracy differences |
| Efficiency | Accuracy alongside total generated tokens, wall time and peak memory |
| Reasoning validity | Separately inspect a prespecified sample of intermediate derivations for valid arithmetic, logical steps and unsupported jumps |

Final-answer correctness measures whether the task was solved; it does not
prove that every written intermediate step is valid or reveal the model's
internal computation. Conversely, longer explanations, confidence and
agreement among samples are not correctness by themselves. Use exact
checks for derivations when available and a documented manual rubric for
steps the current verifier cannot check. Do not use the model's own score
as the sole quality judge.

* 7. Troubleshooting and the implementation map

- Missing extension or tokenizer: check the printed path and the download
  recipe; required missing data returns status 77.
- Facade hash mismatch: review the dependency revision before changing pins.
- Native-handle function failure: current adapters box handles for R13.
  Empty token decode returns empty text locally; native nonempty errors fail.
- CUDA fallback: the selected build is CPU-only; a successful CPU result
  does not validate GPU dispatch. No sudo action is needed for this guide.
- Weight loading errors: see [[file:tensor-loader.md][the tensor loader contract]] and preserve the
  error rather than retrying with unverified or differently shaped artifacts.
