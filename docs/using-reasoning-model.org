* What can be used today

This document explains *how to run the project*. The companion
[[file:reasoning.org][How it works]] document explains the implementation, with annotated MLPL
blocks that reproduce the library files through tangling.

As of 2026-09-28, verifier, synthetic-model generation, scoring and scripted
refinement are runnable. The real tokenizer and verified downloads work
with the [[file:extension-integration.md][documented adapters]]. The named-tensor loader passes authored-file
tests. The bounded real-checkpoint attempt is documented below. No trained
reasoning checkpoint, real-model accuracy or learning improvement is claimed.

Open this file in Emacs Org mode. Enable shell Babel evaluation in your own
Emacs configuration, inspect each block, then use =C-c C-c= to run it.
Blocks run from the repository root via =:dir ..=. They respect your Babel
confirmation setting and never run merely by opening or exporting this document. MLPL code lives
in the implementation document; this guide uses the same thin shell recipes
that an operator runs from a terminal.

* 4. Obtain verified artifacts and check tokenization

The read-only adjacent =demo-extensions= checkout supplies packaged Linux
libraries. =EXTENSIONS_ROOT= can select another checkout; =HFTOK_LIBRARY=
and =HTTP_LIBRARY= select explicit absolute binaries. Public facade hashes
are pinned and checked. Each run prints the selected native binary hash.

This block downloads the tokenizer and configuration if absent, or checks
and reuses valid cached files. Data stays under ignored =models/=. It uses
the pinned revisions, sizes and SHA-256 values in [[file:../catalog/artifacts.jsonl][the manifest]]. It does
not download the 1.19 GB weights.

#+begin_src sh

#+end_src

Acceptance requires six fixture cases, eight real-Qwen goldens and NFC.
Missing real data and wrong ids or round trips fail; fixture-only acceptance
must be requested explicitly and does not establish real tokenizer parity.

* 5. Bounded real-checkpoint viability

The Linux CPU attempt is separate from =just check=. After fetching weights,
this command rechecks their SHA-256 and runs the MLPL driver under a
600-second wall deadline and a 32 GiB virtual-memory limit. It requests two
greedy tokens for the bare base-model prompt =The capital of France is=.
Template =base-smoke-v1= records seed 42 (unused by greedy), EOS 151643 and
all generated ids. There is no chat wrapper or thinking instruction.

#+begin_src sh
<<tested-tools>>
just real-model-smoke
#+end_src

*Result: unavailable within the budget.* The loader never returned, so
generation did not start. The sampled peak is about 14.14 GiB; no completed
load time, generated continuation, tokens/second or accuracy can be reported.
The next task profiles loader copying and allocation before another bounded
attempt. Continue using the fixture demos for generation/scaling examples.

The seven-position rotary allocation is deliberately small. The config guard
checks the pinned base checkpoint's actual 32,768-position limit, along with
dimensions, activation, rotary convention and tying. A shape-compatible but
semantically different checkpoint fails. See [[file:real-model-smoke.md][the measurement report]] for
the full hashes, result and limits. Required missing artifacts return 77;
hash failures never start inference. A timeout returns 124 from the script
(=just= may translate this into its own nonzero recipe status).

* Real method selection — awaiting responder acceptance

Once the real responder is validated, the guide will show the same prompt
under each supported method, with explicit budgets and provenance:

| Method | What the user controls | Interpretation |
|--------+------------------------+----------------|
| Greedy | Token limit and stop id | Highest-scoring next token |
| Sampling | Seed, temperature, top-p, token limit | A reproducible sampled continuation |
| Self-consistency | Distinct seeds and N | Votes on extracted normalized answers |
| Best-of-N | Candidate seeds and scorer | First maximum score, not proof of correctness |
| Refinement | Initial seed and critique/revision pairs | Retain a revision only if score does not fall |

See [[file:sampling.md][sampling]], [[file:self-consistency.md][voting]], [[file:scoring.md][scoring]] and [[file:self-refinement.md][refinement]] for the implemented
contracts. Their APIs exist today; real-model examples still need validation.

MATH-500 is an opt-in download with a pinned digest. Its pinned card does not

The following command tests the verifier against references, not model accuracy.

#+begin_src sh

#+end_src

A future model evaluation must record checkpoint hash, interpreter commit,
example ids, prompt template, seeds, decoding controls, method budget and
scorer. Report attempted/valid/correct counts and failures; never substitute
confidence, vote agreement or reference self-grading for measured accuracy.

* 7. Troubleshooting and the implementation map

- Missing extension or tokenizer: check the printed path and the download
  recipe; required missing data returns status 77.
- Facade hash mismatch: review the dependency revision before changing pins.
- Native-handle function failure: current adapters box handles for R13.
  Empty token decode returns empty text locally; native nonempty errors fail.
- CUDA fallback: the selected build is CPU-only; a successful CPU result
  does not validate GPU dispatch. No sudo action is needed for this guide.
- Weight loading errors: see [[file:tensor-loader.md][the tensor loader contract]] and preserve the
  error rather than retrying with unverified or differently shaped artifacts.
