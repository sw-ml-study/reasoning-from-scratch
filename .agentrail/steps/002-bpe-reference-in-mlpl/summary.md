Implemented lib/tokenizer/bpe.mlpl: the byte-level alphabet built from arithmetic (printable bytes map to themselves, others lift above 255, so a mapped string contains no whitespace and a newline separator for symbol lists is collision-free), a hand-written pre-tokenizer approximating the published seven-alternative pattern with the ASCII-only divergence documented, and the merge loop. The key finding is that no rank table is needed: checking all 151,387 merges of the real tokenizer shows vocab id of a merged token equals rank plus 256 exactly, with no exceptions, so the vocabulary serves as the rank table and the lowest id is the highest priority; u:tok_merge_base verifies the invariant rather than assuming it and refuses a tokenizer where it fails. Pre-tokens are returned as boundary indexes rather than a joined string because a pre-token may contain a line break. Verified correct on the real tokenizer: hello encodes to 14990 and a leading-space the to 279. Measured that it is unusable at production scale: one vocabulary lookup costs 0.0026 ms on a two-field record and 34 ms on the 151,643-field one, so encoding hello world takes 5.9 s and the twelve-thousand-prompt corpus is out of reach. Added probes/record-lookup-scaling.mlpl pinning the linear cost and filed upstream request R10 with acceptance criteria; this is measured evidence for the existing decision that the production encoder is a native extension. Seven tests cover the alphabet, mapping, pre-tokenization boundaries including the give-back-one-space rule, the invariant, merge ordering, every expected id sequence in the fixture, and an out-of-vocabulary error.
