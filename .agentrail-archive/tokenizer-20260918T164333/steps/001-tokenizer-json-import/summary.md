Implemented lib/tokenizer/import.mlpl and measured the real file. A production tokenizer.json cannot be parsed in one call: added_tokens is an array of objects, which parse_json refuses by design, so the whole-document parse fails at byte 271. The import locates each section by anchor and parses them separately, and anchor direction matters because a vocabulary token can be the word vocab, so the real vocabulary key is the first occurrence while the merge list is the last. Added tokens are collected with targeted str_find scanning after measuring that the generic array-to-JSON-Lines scanner costs 15.5 ms at 400 characters and 135 ms at 1600, growing with the square of its input; the targeted reader does the section in 53 ms. Also fixed that scanner to flatten raw newlines so a pretty-printed array becomes valid JSON Lines, since this document is pretty-printed. Measured on the real 6,244,779-character file: vocabulary 151,643 entries in 242 ms, merges 151,387 in 274 ms, added tokens 22 in 53 ms, full cold import 17.4 s because moving a record of 151,643 fields across a call boundary costs about 135 ms each time, native cache 5,467,486 bytes written in 107 ms and read back in 173 ms, peak 942 MB. Recorded that the base tokenizer has no think token, which matters for the format reward in Saga 5.
