Implemented cached generation. Added u:qwen_attention_cached and u:qwen_block_cached to the model, which rotate only the new positions' keys because rotation is a property of a token's position rather than of when it is read, and otherwise reuse the uncached functions so there is one implementation of attention rather than two that could disagree. lib/generate/generate.mlpl holds every layer's history in one stacked array, since the language has no list of records, and runs prefill and single steps through one function because the causal mask already accepted an offset. Greedy decoding stops at a stop id without emitting it and bounds itself with a budget; an empty prompt is a classified error. Six tests, the central one being that cached scores are bit-identical to full recomputation after prefill, one step, and two steps, difference exactly zero. Measured and reported honestly: eight cached steps take 14.4 ms against 13.6 ms for eight full recomputations, so at width 16 with two layers the cache is correct but not an optimization, because reading the stacked cache copies it, which is the container cost already filed as R10. The demo says so plainly rather than claiming a saving, and the ledger records it with the note that the comparison must be repeated at the real configuration. 77 tests pass, fourteen sources tangle, just check passes with the new demo in it.
